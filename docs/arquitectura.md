# Arquitectura — MaestrIA

| Capa / decisión | Tecnología elegida | Alternativas consideradas | Justificación técnica | Riesgos o limitaciones |
|---|---|---|---|---|
| **Plataforma móvil** | Android nativo (Kotlin) | Flutter, React Native | Acceso directo a APIs del dispositivo, mejor integración con Jetpack y Material Design; audiencia objetivo usa Android | Curva de aprendizaje de Kotlin/Android; no hay versión iOS |
| **UI** | XML Layouts + ViewBinding | Jetpack Compose, Flutter Widgets | Compatibilidad con la versión mínima (API 24) sin restricciones; Material Components DayNight para modo oscuro nativo | Más verboso que Compose; separación manual de lógica de vista |
| **Navegación** | Navigation Component (Safe Args) | Intents explícitos, Backstack manual | Gestión centralizada del back stack, paso de argumentos tipado en tiempo de compilación, integración con ViewModel | Configuración del grafo puede volverse compleja al crecer la app |
| **Estado / lógica de UI** | ViewModel + LiveData + StateFlow | MVI con StateFlow, RxJava | Sobrevive cambios de configuración (rotación), separa lógica de negocio de la vista; patrón MVVM estándar en Android | Mal uso de LiveData puede duplicar observadores o generar memory leaks |
| **Inyección de dependencias** | Hilt (Dagger) | Koin, Manual DI | Integración oficial con Android, soporte nativo para ViewModel, Fragment y WorkManager; reduce boilerplate vs Dagger puro | Tiempo de compilación mayor con kapt; errores de DI solo visibles en build |
| **Persistencia local** | Room (SQLite) | DataStore, SharedPreferences, Realm | Consultas tipadas, soporte de corrutinas, caché de materias y datos de sesión del usuario | Requiere migraciones al modificar el esquema; overhead para datos simples |
| **Persistencia remota** | Cloud Firestore (Firebase) | Supabase, API REST propia, Realtime Database | Base de datos NoSQL multiusuario en la nube, sincronización automática, SDK oficial para Android | Reglas de seguridad deben configurarse correctamente; costos al escalar lecturas/escrituras |
| **Autenticación** | Firebase Authentication | Supabase Auth, Auth0, API propia | Manejo de sesión, registro, login, recuperación de contraseña y verificación de correo out-of-the-box | Dependencia total de Google; configuración de reglas de privacidad y cumplimiento (GDPR) |
| **Red / API de IA** | Retrofit 2 + OkHttp + Gson | Ktor Client, Volley | Estándar de facto en Android para consumo de APIs REST; interceptores para token Bearer, soporte Multipart para OCR | API apunta a IP local (192.168.1.9); requiere cambio a URL de producción para distribución |
| **Funciones de IA** | API REST propia (backend externo) | OpenAI SDK, Google Gemini SDK directo | Abstrae el modelo de IA subyacente, permite cambiar el LLM sin modificar el cliente Android | Latencia de red; sin modo offline; dependencia del servidor propio |
| **Renderizado de contenido** | Markwon 4.6 + Prism4j 2.0 | WebView con marked.js, Compose Markdown | Renderiza Markdown en vistas nativas sin WebView, resaltado de sintaxis de código con Prism4j | No soporta todas las extensiones de Markdown; prism4j-bundler requiere anotación manual de lenguajes |
| **Carga de imágenes** | Glide 4.16 | Picasso, Coil | Manejo eficiente de caché de imágenes, soporte para placeholders y transformaciones; amplia adopción en Android | Requiere kapt para el generador; configuración adicional para cargar desde URIs locales |
| **Monitoreo de fallos** | Firebase Crashlytics | Logcat, Sentry, AppCenter | Reporte automático de crashes en producción, agrupación de errores, integración nativa con Firebase | Requiere configuración del plugin; datos de crash se envían a servidores de Google |
